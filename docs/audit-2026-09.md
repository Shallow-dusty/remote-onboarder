# 2026-09-13 安全与交互审计

范围：PowerShell 5.1 载荷、WSL 构建器、Go 日志接收器与浏览器界面。
保持 Windows 单 EXE / IExpress / PowerShell 控制台 / Go 标准库架构；不引入
WebView、前端框架、数据库、多租户或自动部署。本轮没有读取真实构建配置，
没有对开发机或远端执行安装、服务、防火墙、Tailnet 变更。

## 可以保留并借鉴的设计

- 发送方预配置、接收方少决策；连接信息是明确的最终交付物。
- 根据服务和二进制共同判断已安装状态，不把服务注册等同于可执行文件存在。
- 可重复配置、逐步反馈、本地日志、可选远程日志与内嵌载荷。
- 单文件分发不依赖 WebView2，适合可信协助者的一次性接入。

## 发现与处理

| 编号 | 风险/交互问题 | 本轮处理 |
|---|---|---|
| R01 高 | 构建输入直接替换 PowerShell 单引号字符串，可把注释/URL 变成代码 | 独立纯数据 renderer，输入校验、单引号转义、一次替换；不把凭据注入环境变量 |
| R02 高 | 下载后现算 SHA-256 作为信任值，不是文档声称的版本固定哈希 | 两个硬编码 pin，HTTPS 初始/重定向限制，partial 文件与官方签名/发布者复核 |
| R03 高 | 添加窄规则不排除已有宽规则，最终检查只看自家规则 | ActiveStore 默认策略与所有适用于 sshd 的入站 allow 清单；含 Any/range；只禁用明确旧 OpenSSH TCP-22 规则，陌生/GPO/复杂规则阻止 |
| R04 高 | 顶部 Port 22 不消除已有 Port；Match 可覆盖认证配置 | 删除旧顶层 Port；仅支持准确默认管理员 Match，复杂策略预先阻止；最终检查 sshd -T |
| R05 高 | 失败恢复仅覆盖 config，公钥、ACL、服务、防火墙残留 | 改配置前 CLIXML 原状态快照与 pending 标记；普通失败尝试恢复，失败/中断明确要求人工核查 |
| R06 高 | 多次双击和跨工具变更无互斥 | 与 SSH Launchpad 共用系统 mutation mutex；持有至配置/恢复结束 |
| R07 高 | 不同/未知 Tailnet 使用 reset + force-reauth，可能切断路径 | 禁止强制切换；只在确认未登录状态用内置 key；SSH 会话调用前后均阻止 |
| R08 中 | QuietOutput 的失败详情仍可能泄露 auth key | 事件入口和异常消息统一脱敏，接收器补充脱敏；不把 QuietOutput 当作保密保证 |
| R09 中 | 无端点仍排队；SelfTest 会上传真实机器身份 | 空端点立即跳过；SelfTest 强制关闭网络上传，使用唯一临时目录并清理 |
| R10 中 | 删除损坏服务后尝试安装，破坏原恢复路径 | 支持 MSI 路径使用 MSI repair，不预删服务；capability/陌生路径交由原机制 |
| R11 中 | 超时后子进程/系统安装服务可能继续运行 | 不假定 Kill 等于全部结束；持久化未确认安装标记，停止自动并发恢复 |
| R12 中 | 日志无认证、默认监听全部地址、无限写盘 | 默认 loopback、明确私有代理授权边界；事件/会话/总空间上限、禁止缓存/嵌入、拒绝链接文件；未增建账号系统 |
| R13 交互 | 刷新抢滚动、无错误状态、会话按钮拼 HTML | DOM 文本构造、搜索/选中态/暂停/跟随开关、隐藏时停轮询、无重叠请求、失败保留内容 |
| R14 交互 | 成功/重试文案过度承诺，连接信息不区分本机/远端验证 | 明示本机通过仍需控制电脑试连；失败保留现场；展示不可逆边界与下一步 |

## 验证方式

- Python renderer：四组测试（数据引用、注释/URL 单引号、非法输入、marker 不递归替换）。
- PowerShell 5.1 安全 fixtures：策略拒绝、幂等变换、端口集合、凭据脱敏、防火墙
  mock、临时文件快照与恢复；不调用真实服务/防火墙命令。
- 生成载荷构建 `--validate-only`：使用合成密钥配置和已缓存的固定 MSI，核对
  两个哈希、官方签名与发布者，解析 PS 5.1，运行原有 SelfTest。没有打包新的
  EXE、没有覆盖桌面已有版本。新增 safety.ps1 包含在普通打包与解包比对清单。
- Go 接收器 race / vet：请求约束、保存、脱敏、存储上限、链接拒绝、响应头。
- 浏览器：空态、选中、文本注入、搜索、暂停、失败保留、桌面/360px 窄屏。
  截图位于 `build/audit/dashboard/`，全部为模拟会话。

## 未解决为“已保证”的边界

1. **未执行真实目标机验收**：MSI 修复、ACL 与有效 GPO、不同 Windows 版本、
   断电恢复、UAC、IExpress 新包分发，仍需用户批准的隔离目标机验收。
2. **不是完整系统事务**：软件安装、host keys、Tailnet 登录不回滚；MSI 自身可启动
   服务或修改规则。配置快照在安装后取得，不能撤销安装器的全部副作用。
3. **恢复不是盲目重放**：pending 文件必须结合实际状态处理，不能单纯删除绕过。
   超时和强制终止后的进程树状态不能靠脚本成功退出证明。
4. **日志服务未内置认证**：默认 loopback 不保护显式对外监听；Docker 私网也不是
   面向所有网络的授权。公网部署必须另有访问控制，尤其是 `/sessions` 的身份信息。
   此轮未检查、更改任何线上代理/端点。HTTPS 只保证传输，不授予权限。
5. **内嵌凭据可提取**：不增加加密/签名分发，接收方本地管理员是信任边界。
   使用短有效期、合适授权范围的 key，妥善保管 EXE。expectedTailnet 校验不防止
   泄漏的 key 被使用。运行时 key 短暂出现在 tailscale 子进程 argv。
6. **保守支持而非覆盖一切**：陌生 SSH/GPO/宽防火墙策略会被阻止，不自动“修复”
   为简单配置。这是有意保留的支持范围，不应通过忽略报错提升成功率。
